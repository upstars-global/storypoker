# Аудити Story Poker

Ця папка зберігає завершені аудити як датовані історичні знімки. Новий аудит додається окремим
файлом `YYYY-MM-DD-<topic>-audit.md`; попередні висновки не переписуються через подальші зміни
коду.

Якщо після завершення аудиту знайдено фактичну помилку, її можна виправити з явною датованою
приміткою. Повторна перевірка стану оформлюється новим аудитом.

Статус виправлень живе не тут, а в [`docs/roadmap.md`](../roadmap.md).

## Індекс

- [2026-09-07 — аудит фронтенду](2026-09-07-frontend-design-audit.md): `frontend-crafting` 1.2.1,
  статичний review усіх 33 `.vue` і `main.css` — 2 системні знахідки + 9 ізольованих.
  Системні: нуль `prefers-reduced-motion` при трьох `@keyframes` (салют, блимання переможця, джем
  барабана) і `lang="uk"`, зашитий в `index.html`, який не слідує за перемикачем мови. Ізольовані:
  кімната без `<main>` і без `<h1>`, три icon-only кнопки з `aria-describedby` замість імені,
  тумблер прапорця у `/ffc` недосяжний з клавіатури, відсутній skip-link, `AppModal` без повернення
  фокуса на тригер (9 модалок), меню `role="menu"` без стрілок, беззвучний rollback голосу, кімната
  без власного `<title>` і зашиті пороги Goal Clarity.
  Runtime-перевірок немає: контраст шести комбінацій `palette × theme`, touch-таргети й
  горизонтальний overflow лишаються відкритими до аудиту `web-debug`.

## Дані

- [`icon-bundle-baseline.json`](icon-bundle-baseline.json) - gzip entry chunk на `main` до переходу іконок на
  локальну доставку. Проти нього `npm run icons:audit-build` рахує дельту з бюджетом 25 KB gzip.
  Це не аудит, а вимір. Entry chunk у проєкті один і не сплітиться, тож будь-який неіконковий приріст теж їсть
  цей бюджет. Коли він вичерпається не через іконки - перезняти baseline з поточного `main`
  (`npm run build && node -e ...` як при першому знятті), записати новий `commit` і `gzipBytes`, і в тому ж
  коміті пояснити причину. Мовчки піднімати поріг у скрипті не можна.

## Конвенції

- **Мова:** українська, як і решта внутрішньої документації (`AGENTS.md`, `DESIGN.md`, `docs/`).
- **Шапка аудиту:** дата, гілка з SHA, скіл і його версія з робочим процесом, обсяг у файлах,
  формат доказів (статичний аналіз проти runtime) і посилання на попередній аудит тієї ж теми.
- **Два шари окремо:** візуальна й досвідна критика (Layer 1) не змішується з технічними
  знахідками (Layer 2) в одному списку.
- **Кожна знахідка** несе location, issue, severity (P0–P3), user impact, standard і remediation —
  включно з P3.
- **Системні знахідки** (той самий дефект у трьох місцях або спільна причина в токені/компоненті)
  ідуть перед ізольованими.
- **Чистий baseline** із названим обсягом перевірки — це доказ, а не порожній розділ.
- **Аудит не змінює код.** Ремедіація описується, а не застосовується; виправлення — окрема сесія.
