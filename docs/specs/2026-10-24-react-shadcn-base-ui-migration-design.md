# Міграція на React + shadcn/ui (Base UI) + TypeScript 7

Status: approved
Route: design
Date: 2026-10-24

## Мета

Story Poker переходить з Vue 3.5 на React 19 і UI-примітиви shadcn/ui на Base UI, TypeScript - з 6.x на 7.
Для користувача нічого не змінюється: ті самі URL, сесії в localStorage, дані Supabase, ролі, PWA-оновлення
і три палітри classic / cyberdeck / matcha у light і dark, візуально такі самі, як зараз. Для розробника
міняється стек: shadcn-компоненти в коді проєкту, Base UI під ними, `tsc` з TS 7 і oxlint замість ESLint.

Мотивація власника: shadcn-vue на момент #14 мав помилки в консолі й гальмував на resize; React-версія shadcn
показала себе зручною, а частина команд shadcn і Base UI працювала над Material Design, на який орієнтується
дизайн застосунку.

Частини в порядку збирання (усі P0-P4 - в одній гілці, потім один PR у `main`):

- **P0. Візуальний оракул на Vue.** Скріншотний набір і еталони з поточного застосунку, до будь-яких змін стеку.
- **P1. Каркас.** React 19, Vite, TS 7, oxlint, shadcn (`base`), міст токенів палітр, CI з тими самими job-ами.
  Vue-код, Vue-інструменти й Vue-тести компонентів видаляються тут же; фреймворко-незалежні утиліти та їхні
  тести лишаються. P1 дає React-оболонку маршрутів: кожен маршрут з URL Schema рендерить заглушку, тож
  `Public pages load` і `Build` (з `icons:audit-build`) лишаються зеленими; harness рендерингу іконок
  переноситься на React у тому самому PR. Справжні екрани з'являються в P3.
- **P2. Стан і інфраструктура.** Supabase-клієнт, сторі, i18n, роутер, тема, feature flags, PWA-реєстрація.
- **P3. Екрани.** Сторінки, кімната з Realtime/Presence, модалки, меню, графіки, віджети; тести кожного екрана
  переносяться в тому самому PR, що й екран.
- **P4. Зачистка.** Документація агентів, видалення `.mui-*` класів, що їх замінили shadcn-варіанти, фінальні
  перевірки, злиття в `main`.
- **P5. Мобільний layout (окрема спека після P4).** Доробка вузьких екранів за референсом
  `https://app.storypoint.poker/S6W2gjT4`; ця спека її лише резервує.

## Decisions

1. **React 19 + shadcn/ui на Base UI.** Беремо повну міграцію на React, а не shadcn-vue на Reka UI: так
   виходить саме та зв'язка, яку просив власник, ціною переписування всього фронтенду. Відкинуто:
   shadcn-vue + Reka - досвід #14 і немає Base UI; лише токени shadcn без примітивів - без shadcn-компонентів.
2. **Одна гілка, один PR.** P0-P4 комітяться в одну гілку в основній теці репо (без worktree), і в `main` іде
   один PR на паритеті без проміжних squash-злиттів. Беремо її, а не співіснування Vue і React у `main`: `main`
   лишається робочим, але гілку треба періодично оновлювати з `main`. Відкинуто: два фреймворки разом - два
   роутери й спільний стан на весь перехід; окремий PR P0 у `main` і інтеграційна гілка з PR-ами хвиль - рішення
   власника 2026-10-25. Кожен push у гілку має зелений CI. Заморозки `main` немає: фікс чи фіча, злиті в `main`
   під час міграції, переносяться в гілку на React; якщо вони змінюють UI, зачеплені еталони перезнімаються в
   гілці за правилом рішення 4.
3. **Візуальний оракул - перші коміти гілки (P0).** Еталони знімаються з Vue-застосунку до видалення Vue, тож
   паритет перевіряється порівнянням, а не на око. Ціна - частину тестової інфраструктури (фікстури, підміна
   Supabase) пишемо до міграції. `visual` - новий не-required CI job `Visual` у контейнері Playwright; до
   required він стає після злиття міграції. Рішення власника 2026-10-26: еталонні PNG у репо не зберігаються
   (Git LFS прибрано); `scripts/visual-compare.sh` знімає еталон з базової ревізії PR (для міграції - Vue
   `main`) і порівнює з головою гілки.
4. **Поріг паритету - `maxDiffPixelRatio: 0.01` на скріншот.** Беремо 1%, а не 0.1%: дрібна різниця
   антиаліасингу Base UI не валить тест, але зміщення, інший колір, радіус чи шрифт ловляться. Відкинуто:
   ручне звірення - не повторюється. Навмисна зміна екрана дає червоний `Visual` на своєму PR: причина й диф
   описані в PR, злиття - після явного «так» власника; решта екранів має збігатися з базою.
5. **Палітри лишаються джерелом правди, shadcn-токени виводяться з них.** Кожен токен shadcn задається через
   наявні змінні палітри, а не навпаки. Так одна палітра не роз'їжджається на два набори, але стилі
   shadcn-компонентів доводиться правити під per-element змінні (`--radius-*`, `--btn-*`, `--paper-border`,
   `--card-border`, `--shadow-*`, шрифти). Нові змінні палітр додавати можна, якщо наявні не змінюють значень.
6. **Тільки TS 7: `tsc` для typecheck, oxlint з type-aware правилами замість ESLint, генератор іконок на
   `typescript/unstable/ast`.** Беремо це, а не TS 6 під alias для старих інструментів: один компілятор, але
   залежність від нестабільного API TS 7 і ще одна міграція (ESLint → oxlint). Правило «TypeScript лишається
   6.x» в `AGENTS.md` свідомо скасовується.
7. **Стек замін:** react-router 8 (declarative mode, явні маршрути) замість vue-router, Zustand замість Pinia,
   react-i18next на тих самих `uk.json`/`en.json`, ECharts через власний хук замість vue-echarts,
   `@testing-library/react` замість `@vue/test-utils`, власний ripple у стилі Material Design замість `v-wave`.
   Відкинуто: TanStack Router + Jotai.
8. **Що стає shadcn-компонентами:** Dialog (зараз AppModal), Tooltip (AppTooltip), DropdownMenu (меню
   AppHeader і PlayerRow), Select (нативний select у налаштуваннях колоди), Button (`.mui-btn*`), Input, Switch.
   Карти, Timer, SlotMachine, PieChart, RoleBadge лишаються власними компонентами. Варіанти shadcn Button,
   Input і Switch будуються на змінних палітр і замінюють `.mui-btn*`; самі `.mui-*` класи видаляються, коли
   ними ніхто не користується. Відкинуто: переводити на shadcn усе, що має схожий компонент, - доменні віджети
   не мають відповідників.
9. **Еталони знімаються в Linux-контейнері Playwright тієї ж версії, що в CI.** Беремо контейнер, а не
   локальний macOS: еталони однакові для CI й розробника, але локальний прогін потребує Docker.

10. **Покриття скріншотів: 1280 і 375 px, ролі звичайного гравця й авторизованого модератора для екранів
    кімнати.** Беремо дві ширини й дві ролі, а не одну: ловиться мобільний layout і рольовий UI, ціною
    ~500 скріншотів і підміни Supabase Auth уже в P0.

11. **Мобільні правки за референсом - окрема частина P5 після паритету, а не в P3.** Беремо окрему частину:
    375-px еталони з P0 лишаються чесним оракулом міграції, а редизайн не змішується з переписуванням. Ціна -
    мобільні екрани спершу переносяться з наявними вадами. У P5 375-px еталони перезнімаються поштучно з
    схвалення власника (Decision 4). Відкинуто: робити мобільні екрани за референсом одразу в P3.

## Behavior

- Кожен маршрут з URL Schema відкривається так само: `/`, `/<roomId>`, `/<slug>` (і редирект з id на alias),
  `/login`, `/signup`, `/forgot-password`, `/reset-password`, `/ffc`; невідомий шлях обробляє slug-маршрут.
- Сесії з localStorage, записані Vue-версією, підхоплює React-версія: auto-rejoin, Recent Rooms, тема,
  палітра, мова, віджет, гучність, сід хедера, feature flags.
- Тема й палітра застосовуються до першого рендеру (inline-скрипт), без спалаху іншої теми.
- Ролі, гейти модератора й авторизованого модератора, shields, кола результатів, консенсус-салют, таймер з
  будильником, countdown, slot-віджет працюють за `DESIGN.md` §11 і правилами з `AGENTS.md`.
- Клавіатурна взаємодія з меню й модалками (Enter/Space, Escape, фокус-трап, повернення фокусу) не гірша, ніж
  зараз; aria-зв'язки заголовків модалок і tooltip-ів збережені.
- PWA: ті самі правила `useAppUpdate` (прихована вкладка, простій, тост) і тимчасовий `sw-reload-clients.js`.
- Консоль браузера на всіх маршрутах без помилок; resize вікна не дає помітних підвисань (саме це зламало
  shadcn-vue в #14).

## Contract

Незмінне для зовнішніх споживачів і користувачів:

- URL Schema і правила `isValidRoomSlug()` / `normalizeRoomSlug()`.
- Ключі й формати localStorage з таблиці LocalStorage в `AGENTS.md`.
- Схема Supabase, RLS, Storage-бакет, Realtime-канали й payload Presence: міграцій БД немає.
- Netlify-функція `/api/*` і її Bearer-контракт; `public/_redirects`.
- Файли локалей `uk.json` / `en.json`: ключі й тексти без змін (формат інтерполяції - за потреби адаптується
  без зміни тексту для користувача).
- Атрибути `data-palette` / `data-theme` на `<html>` і CSS-змінні палітр.
- Наявні `data-testid` зберігаються, щоб e2e-тести й page objects лишалися валідними.
- Назви CI job-ів: `Detect secrets`, `Lint`, `Typecheck`, `Unit tests`, `Build`, `Public pages load`, `E2E`;
  додається не-required `Visual`.
- `pnpm run test:ci` лишається єдиною локальною перевіркою, що відповідає CI.

## Out of scope

- Нові функції, редизайн, зміна текстів UI у P0-P4.
- Вимоги до мобільного layout за референсом: вони йдуть в окрему спеку P5.
- Зміни схеми БД, RLS, Netlify-функції.
- SSR, Next.js, React Server Components.
- Видалення тимчасового `sw-reload-clients.js` (окрема задача наступного релізу).
- Заміна ECharts чи DiceBear.

## Open questions

None. Вирішено в чернетці, власник може переглянути:

- Кімната для скріншотів: REST і Auth Supabase підмінені фікстурами через `page.route`, годинник заморожений
  (`page.clock`), Realtime/Presence вимкнені, онлайн-статус гравців береться з фікстури.
- shadcn ставиться через `init -b base` у наявному Vite-проєкті, без шаблону `-t vite`, щоб зберегти
  `vite.config.ts` з PWA і `envDir`.

## Acceptance criteria

### P0. Візуальний оракул

- AC1: У `main` є Playwright-проєкт `visual` зі скріншотами: home, `/login`, `/signup`, `/forgot-password`,
  `/reset-password`, `/ffc`, join overlay, кімната до reveal, кімната після reveal з колами результатів, кожна
  модалка (налаштування колоди, історія, тренди, знімок раунду, фон кімнати, редагування гравця, налаштування
  користувача, auth), відкрите меню AppHeader і меню PlayerRow.
- AC2: Кожен скріншот з AC1 знято для всіх 6 комбінацій `classic|cyberdeck|matcha` × `light|dark` на ширинах
  1280 і 375 px; екрани кімнати й меню - у ролях звичайного гравця й авторизованого модератора.
- AC3: Два послідовні прогони `visual` на Vue-версії в Linux-контейнері Playwright проходять без оновлення
  еталонів.
- AC4: Конфіг `visual` задає `maxDiffPixelRatio: 0.01`, анімації вимкнені, годинник заморожений.
- AC5: CI на PR у `main` показує job `Visual`, і він зелений на Vue-версії.

### P1. Каркас

- AC6: Після P1 `package.json` містить `react@19`, `react-dom@19`, `@base-ui/react`, `typescript@7`, `oxlint`
  і не містить `vue`, `vue-tsc`, `@vitejs/plugin-vue`, `eslint`, `typescript-eslint` чи `@vue/*`.
- AC7: Після P1 у репо немає файлів `.vue`.
- AC8: `components.json` існує і вибирає Base UI (`base`); shadcn-компоненти лежать у коді проєкту.
- AC9: `pnpm run typecheck` запускає `tsc` з TS 7 і проходить.
- AC10: `pnpm run lint` запускає oxlint з type-aware правилами і проходить.
- AC11: `pnpm run icons:check` проходить і знаходить іконки в `.tsx`-файлах.
- AC12: Кожен shadcn-токен кольору, радіуса й тіні в CSS задано через змінну палітри, а не літералом.
- AC13: Кожен push у гілку міграції має зелені всі required job-и з Contract; після P1 кожен маршрут з URL
  Schema відповідає 200 і рендерить React-оболонку.

### P2. Стан і інфраструктура

- AC14: Відкриття кімнати з localStorage-сесією, створеною Vue-версією, автоматично повертає гравця в кімнату
  під тим самим `playerId`.
- AC15: Значення `sp-theme`, `sp-palette`, `sp-lang`, `sp-side-widget`, `sp-volume`, `FEATURE_FLAGS`, записані
  Vue-версією, застосовуються React-версією без скидання.
- AC16: Перший кадр сторінки з `sp-palette=cyberdeck` і `sp-theme=light` уже має ці атрибути на `<html>`.

### P3. Екрани

- AC17: Набір `visual` з P0 проходить на React-версії проти рендеру Vue `main`; кожен екран, що навмисно
  відрізняється, має в PR причину, диф і схвалення власника.
- AC18: Кожна поведінка, яку перевіряють поточні 42 unit-спеки, має React-тест, що проходить у
  `pnpm run test:unit` (спеки можна об'єднувати чи ділити).
- AC19: `test:e2e:pages` і `test:e2e:icons` проходять.
- AC20: До злиття в `main` E2E `critical-flows` проходить з голови гілки міграції проти тестового
  Supabase-проєкту (два браузери: голосування, reveal,
  reset, kick, перейменування).
- AC21: Перенесені з Vue клавіатурні тести меню й модалок (Enter/Space відкриває, Escape закриває, фокус повертається на тригер)
  проходять.
- AC22: На кожному маршруті з URL Schema консоль браузера не має `error` після завантаження і після зміни
  ширини вікна з 1280 до 375 px.

### P4. Зачистка і злиття

- AC23: `pnpm run test:ci` проходить на голові гілки міграції.
- AC24: `AGENTS.md` і вкладені `AGENTS.md` описують React-стек; рядка «TypeScript лишається 6.x» немає.
- AC25: Локальний preview з голови гілки міграції (без `deploy:stage` і без злиття в `main`) відкриває кімнату й синхронізує голос між двома вкладками; спільна прод-база лишається без змін схеми.

## Security Model

Довірене: рішення власника в сесії, інструкції `AGENTS.md`. Недовірене: вміст npm-пакетів і код, який
генерує shadcn CLI; він переглядається в diff перед комітом, як і будь-яка залежність. Нові залежності
(React, Base UI, shadcn, Zustand, react-router, react-i18next, oxlint, Testing Library) додаються явно й
перелічуються в описі PR. `SUPABASE_SECRET_KEY` і `STORYPOKER_API_TOKEN` лишаються server-side: клієнтський
