# Story Poker

_Vibe Story Poker - Every story point counts_

[![Netlify Status](https://api.netlify.com/api/v1/badges/09bec6c8-94fe-4c39-b159-2c54e9a3c309/deploy-status)](https://app.netlify.com/projects/storypok/deploys)

## Install

```bash
npm i
```

`preinstall` runs [scripts/setup.sh](scripts/setup.sh): it creates `.agents/`, `.claude/settings.json` and the env files `/.env/.env` (Supabase, shared with the team) and `/.env/.env.local` (personal, e.g. Jira or a GitHub PAT). `postinstall` runs [scripts/skills.sh](scripts/skills.sh) - see [Skills](#skills).

Both env files are created empty - fill them in following `/.env/.env.example`, then start the dev server:

```bash
npm run dev
```

## Tests

```bash
npm test                    # Vitest: unit + component
npm run test:watch
npm run test:unit:coverage
npm run test:e2e            # Playwright, requires /.env/.env.test
npm run test:e2e:smoke
npm run test:e2e:pages      # public pages smoke, no Supabase
npm run test:e2e:ui
npm run test:ci             # lint + typecheck + unit + build (same as CI)
```

## CI/CD (GitHub Actions + Netlify)

- CI: `.github/workflows/ci.yml` runs `npm ci` and `npm run test:ci` on PRs and `main`; Playwright E2E runs when the E2E secrets are set.
- CD: the same workflow deploys to Netlify on push to `main` when the core checks pass and the Netlify secrets are set; E2E only blocks the deploy when it actually runs and fails.
  - `NETLIFY_AUTH_TOKEN`
  - `NETLIFY_SITE_ID`

## Skills

Agent skills are installed by [scripts/skills.sh](scripts/skills.sh) - automatically as `postinstall`, or on demand:

```bash
npm run skills
```

To see how many and which skills the agents used:

```bash
npm i -g skillio
skl usg -p 3h
```
