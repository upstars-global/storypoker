# Story Poker

### Install

```bash
npm i
```

`preinstall` runs [scripts/setup.sh](scripts/setup.sh): it creates `.agents/`, `.claude/settings.json` and empty `.env/.env` + `.env/.env.local`. `postinstall` runs [scripts/skills.sh](scripts/skills.sh) - see [Skills](#skills).

### Run

Fill `.env/.env` (shared: Supabase) following `.env/.env.example`; `.env/.env.local` is the per-user override.
```bash
cp .env/.env.example .env/.env
npm run dev
```

### Quality checks

```bash
npm run lint
npm run typecheck
npm run test
npm run build
npm run test:e2e:pages   # public pages smoke, no Supabase
npm run test:e2e         # full Playwright suite, requires .env/.env.test
```

`npm run test:ci` runs the first four in one go - the same gate as CI.

### CI/CD (GitHub Actions + Netlify)

[.github/workflows/ci.yml](.github/workflows/ci.yml) runs on PRs and pushes to `main`:

- `lint`, `typecheck`, `unit`, `build` and `page-load` (Chromium smoke of the public pages with dummy Supabase credentials) run in parallel on every run.
- `e2e` (Chromium + WebKit against the test Supabase project) runs only when the `E2E_*` secrets are set.
- `deploy` publishes the `build` artifact to Netlify on `main` when every check passed (`e2e` may be skipped, never failed) and `NETLIFY_AUTH_TOKEN` + `NETLIFY_SITE_ID` are set.

### Ports

- `5173` - `npm run dev`
- `4173` - `npm run preview`; Playwright reuses a server already running there unless `E2E_BASE_URL` points elsewhere

### Run Claude Code In Bypass Mode

```bash
claude --dangerously-skip-permissions
```

## How it works

What happens during one estimation round:

```mermaid
sequenceDiagram
  autonumber
  actor Mod as Moderator
  actor Player as Player
  participant App as SPA (Vue + Pinia)
  participant DB as Supabase Postgres
  participant RT as Supabase Realtime + Presence
  participant API as Netlify Function /api/*.json
  participant AC as agilecharts

  Mod->>App: Create room (id or slug), pick a card deck
  App->>DB: insert rooms + room_state (phase: voting)
  Player->>App: Join by URL, choose name + role
  App->>DB: insert players
  App->>RT: join Presence channel room:<roomId>
  RT-->>App: online players
  Player->>App: Pick a card
  App->>App: optimistic vote (pendingVotes)
  App->>DB: update players.vote
  DB-->>RT: postgres_changes players:<roomId>
  RT-->>App: everyone sees "voted" (values stay hidden)
  Mod->>App: Reveal (optional hold-to-start countdown)
  App->>RT: broadcast countdown:<roomId> (self: true)
  RT-->>App: synchronized countdown on every client
  App->>DB: room_state.phase = revealed
  App->>DB: insert round_history snapshot (votes >= 2)
  DB-->>RT: postgres_changes room_state:<roomId>
  RT-->>App: cards flip, stats + consensus celebration
  Mod->>App: New round
  App->>DB: reset votes, phase = voting, round_started_at = now
  Note over App,RT: tab hidden > 5 min closes Presence; visible again refetches state
  AC->>API: GET /api/<room>.json (Authorization: Bearer)
  API->>DB: rooms + round_history + players
  API-->>AC: rounds with average, DEV/QA alignment, per-player votes
```

Have fun! ;)
